## 2. Regresi yang WAJIB diperbaiki

### 2a. Test suite: 7 gagal — semuanya TEST BASI (bukan bug produk)
Kode produk membaik, tetapi test tidak ikut diperbarui:

1. **5× `PosCheckoutTest`** — DTO `CartLine` berubah menjadi `(string $tipe, int $itemId)`, tetapi test masih memanggil `new CartLine($produk->id, 2)` → `TypeError: argument $tipe must be string, int given`.
2. **1× `AnalyticsTest`** — judul view diterjemahkan `"Sales Analytics" → "Analisis Penjualan"`, tetapi test masih `assertSee('Sales Analytics')`.
3. **1× `ServiceTicketTest`** — format resi menjadi acak (`PK-2026-UQTPZM`), tetapi test masih mengharap pola lama `/^PK-\d{4}-\d{4}$/`.

→ **Akar: test tertinggal saat kode diperbaiki.** Perbaikan = sinkronkan pemanggilan/assersi ke API & format baru.

### 2b. Static analysis: 11 error — campur bug nyata & false-positive
**Bug nyata (perbaiki):**
- `TransaksiController:42` — `!==` antara enum `TransaksiStatus` dan string `'Normal'` → **selalu true**. Logika status transaksi (mis. filter void/normal) tidak pernah bekerja sesuai maksud. Bandingkan `->value` atau case enum, bukan string mentah.
- `Transaksi::$nomor_transaksi` — properti/kolom tidak ada (kemungkinan maksudnya `kode_nota`).
- `Cannot access property $value on string` — `->value` dipanggil pada nilai yang sudah string → potensi `TypeError` saat runtime.
- `fputcsv(...)` tipe argumen tidak sesuai → **export CSV bisa error** pada baris tertentu.
- `Unreachable statement` → dead code (bersihkan).

**Kemungkinan false-positive (alias `DB::raw`):**
- `ItemTransaksi::$total_profit / $harga_satuan / $total_pendapatan` — alias dari `SELECT SUM(...) as ...` yang tidak terlihat phpstan. Amankan dengan DTO/`->getAttribute()` atau pastikan query benar.
